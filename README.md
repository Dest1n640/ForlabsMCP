# forlabs-mcp

Локальный сервер [MCP](https://modelcontextprotocol.io), который заходит в
SPA школьного дневника Forlabs/Lamotivo (`bki.forlabs.ru/app`) под учётной
записью студента и предоставляет восемь безопасных MCP-инструментов для
расписания, предметов и заданий. Отправка ответа — отдельный девятый
инструмент `submit_assignment_response`, который по умолчанию вообще не
регистрируется.

Общие RPC-вызовы проходят через read-only allow-list. Отправка ответа
использует отдельные фиксированные операции, включается только через
`FORLABS_ENABLE_ASSIGNMENT_SUBMISSION=true`, работает без автоматического
повтора и требует предварительного просмотра. Экзамены, оценки, посещаемость
и произвольные записи не изменяются. Локально сервер сохраняет кеш cookie
(права `0600`); файлы прикрепляются только после preview и только из
`FORLABS_UPLOAD_ROOT`.

**Пароль от аккаунта серверу вообще не нужен.** Аутентификация — через
долгоживущий cookie `remember_lm_<hash>` (~5 лет), который вы один раз
копируете из уже залогиненной сессии в браузере — см. «Конфигурация»
ниже.

## Требования

- Python 3.11+
- [`uv`](https://docs.astral.sh/uv/)
- Учётная запись студента Forlabs/Lamotivo, в которую вы уже залогинены
  в браузере (нужно один раз скопировать оттуда cookie — см. ниже)

## Установка

```bash
git clone https://github.com/Dest1n640/ForlabsMCP.git
cd forlabs-mcp
uv sync
```

После этого проверить, что всё встало корректно, можно так:

```bash
uv run pytest
```

Все тесты работают на синтетических фикстурах, без обращения к реальному
backend'у и без необходимости иметь настроенный токен.

## Подключение к MCP-агенту

Вставьте этот JSON в конфиг вашего MCP-агента (Claude Desktop, Claude
Code, Cursor и любой другой клиент, принимающий `command`/`args`/`env`) и
замените два плейсхолдера: путь к репозиторию и свой session token.

```json
{
  "mcpServers": {
    "forlabs": {
      "command": "uv",
      "args": ["--directory", "<абсолютный-путь-к-этому-репозиторию>", "run", "forlabs-mcp"],
      "env": {
        "FORLABS_SESSION_TOKEN": "<ваш-session-token>"
      }
    }
  }
}
```

Хосты с другой обёрткой (например, `claude mcp add-json` или YAML-конфиг)
принимают те же три поля: `command`, `args`, `env`.

### Где взять session token

1. Откройте `https://bki.forlabs.ru/app` в браузере и залогиньтесь как обычно.
2. DevTools → вкладка **Application** (Chrome) / **Storage** (Firefox) →
   Cookies → `https://bki.forlabs.ru`.
3. Найдите cookie с именем, начинающимся на `remember_lm_`, и скопируйте
   его **Value**. (Он помечен `HttpOnly` и не виден через
   `document.cookie`, но в списке cookie в DevTools отображается.)

Это разовое действие: срок жизни такого cookie — около 5 лет, обычные
запросы сами продлевают короткоживущую сессию. Обращайтесь с токеном как
с паролем: он даёт полный доступ к аккаунту на весь этот срок.

### Альтернатива: JSON-файл в репозитории

Вместо `env` можно положить токен в файл:

```bash
cp forlabs-session.example.json forlabs-session.json
```

Затем замените значение `session_token` в `forlabs-session.json` на свой
токен. Файл добавлен в `.gitignore` и не попадёт в коммит; в git лежит
только шаблон `forlabs-session.example.json` с плейсхолдером. Тогда блок
`env` в JSON выше нужно убрать целиком, а не оставлять пустым или с
`"${FORLABS_SESSION_TOKEN}"`. Хосты, которые не подставляют `${...}` в
`env` (например, Hermes Agent), передают эту строку серверу буквально;
сервер игнорирует такие значения и печатает в stderr предупреждение с
именем переменной, после чего читает токен из файла. Путь к файлу можно
переопределить переменной `FORLABS_TOKEN_FILE`.

## Настройки

Приоритет: **переменная окружения > `forlabs-session.json` > значение по
умолчанию** для настроек, поддерживающих JSON-файл. Ключи безопасности
`FORLABS_ENABLE_ASSIGNMENT_SUBMISSION` и `FORLABS_UPLOAD_ROOT` принимаются
только через окружение; нераскрытый `${...}` считается незаданным.

| Настройка | Переменная окружения | По умолчанию | Обязательна |
|---|---|---|---|
| Session token (значение `remember_lm_<hash>`) | `FORLABS_SESSION_TOKEN` | — | да |
| Base URL | `FORLABS_BASE_URL` | `https://bki.forlabs.ru` | нет |
| Таймаут (сек.) | `FORLABS_TIMEOUT_SECONDS` | `30` | нет |
| Часовой пояс | `FORLABS_TZ` | `Asia/Irkutsk` | нет |
| Путь к кешу сессии | `FORLABS_SESSION_PATH` | `~/.local/state/forlabs-mcp/session.json` | нет |
| Максимум элементов в списке | `FORLABS_MAX_ITEMS` | `200` | нет |
| Отправка ответов (принимает `true`/`1` или `false`/`0`) | `FORLABS_ENABLE_ASSIGNMENT_SUBMISSION` | `false` | нет |
| Корень доступных локальных вложений | `FORLABS_UPLOAD_ROOT` | — | нет |

Проверка токена происходит до любого сетевого запроса. Если токена нет
ни в одном источнике (или в файле остался плейсхолдер), сервер сразу
завершается с ошибкой конфигурации.

### Обновление со старой настройки

Раньше токен мог храниться в `~/.config/forlabs-mcp/config.toml` (его
создавал wizard `scripts/setup_config.py`). Этот файл и скрипты удалены и
больше не читаются: перенесите токен в `env` или в `forlabs-session.json`.

## Безопасность

Репозиторий публичный, поэтому в нём не должно быть токенов, реальных имён
и локальных путей. Защита в два слоя, оба используют `tools/leakscan.py`:

- `uv run pytest` проверяет **все отслеживаемые git файлы** (README, код,
  документы, фикстуры). Файл `forlabs-session.json` в `.gitignore` не
  читается.
- Необязательный pre-commit хук проверяет то, что вы собираетесь
  закоммитить. Включается один раз на клон:

  ```bash
  git config core.hooksPath .githooks
  ```

Сканер ловит известные формы секретов (значения кук Laravel и XSRF, JWT,
ключи GitHub/OpenAI/AWS, приватные ключи, bearer-токены), ФИО не из
списка синтетических и абсолютные пути `/Users/…`, `/home/…`. В отчёте
только файл, строка и название правила, само значение не показывается.
Это сигнализация о знакомых формах, а не доказательство отсутствия
секретов. Обойти хук можно через `git commit --no-verify`, но `pytest`
всё равно провалится.

**Ручная уборка после перехода на `forlabs-session.json`** (сервер эти
файлы не удаляет и не читает):

1. Старый `~/.config/forlabs-mcp/config.toml` больше не используется, но
   может хранить ваш токен. Перенесите значение в `forlabs-session.json`
   или в `env` MCP-хоста и удалите файл.
2. `~/.local/state/forlabs-mcp/session.json` содержит живые куки
   (права `0600`). Это нормальный кеш сессии, храните его как пароль.
3. По желанию: `git gc --prune=now` удалит из локального репозитория
   висячие объекты, оставшиеся после переписывания истории.
4. По желанию: в настройках GitHub (Email) включите «Block command line
   pushes that expose my email», чтобы личный адрес не попадал в коммиты.

### Отправка ответов по заданиям

- По умолчанию `submit_assignment_response` отсутствует в MCP-каталоге.
  Включайте его только если MCP-хост запрашивает подтверждение перед
  изменением данных: аннотация инструмента — подсказка, не механизм
  принуждения.
- Сначала `preview_assignment_response` проверяет задание, нормализует текст
  так же, как сайт, и возвращает одноразовый `preparation_id` сроком на
  10 минут. Сам submit принимает только этот ID; повторная попытка требует
  нового preview.
- Без вложений достаточно текста. Для вложений задайте `FORLABS_UPLOAD_ROOT`;
  разрешены только обычные файлы внутри него, максимум 50 MiB на файл.
  Preview не показывает локальные пути или хеши, а отправка проверяет, что
  файлы не изменились после просмотра.
- Запрос отправки и загрузка чанков не повторяются автоматически. При
  неоднозначном результате инструмент перечитывает ветку ответов и просит
  проверить её вручную, а не отправляет дубль. Live smoke не включает файлы.

Для включения добавьте `FORLABS_ENABLE_ASSIGNMENT_SUBMISSION=true` в
окружение MCP-сервера. Если нужны вложения, дополнительно задайте
`FORLABS_UPLOAD_ROOT` отдельной директорией с разрешёнными файлами. Тогда
блок `env` в конфиге хоста (см. «Подключение к MCP-агенту») выглядит так:

```json
"env": {
  "FORLABS_SESSION_TOKEN": "<ваш-session-token>",
  "FORLABS_ENABLE_ASSIGNMENT_SUBMISSION": "true",
  "FORLABS_UPLOAD_ROOT": "<абсолютный-путь-к-папке-с-файлами>"
}
```

Если вложения не нужны, строку `FORLABS_UPLOAD_ROOT` можно не добавлять:
текстовые ответы работают и без неё.

## Tool'ы

- **`reference()`** — идентификатор своего потока, доступные потоки
  расписания и список собственных предметов; параметра выбора группы нет.
- **`schedule_groups()`** — каталог групп, которые можно выбрать именно для
  расписания; это не список предметов.
- **`schedule(date?, start?, end?, stream_id?)`** — расписание на реальные
  календарные даты. Без `stream_id` используется своё расписание; для другой
  группы сначала получите ID через `schedule_groups()`.
- **`grades(study_id?)`** — оценки только по собственным предметам.
- **`homework(study_id?, only_outstanding?)`** — задания только по собственным
  предметам, опционально только невыполненные.
- **`assignment_details(study_id, task_id)`** — описание конкретного задания
  и его assignment.
- **`assignment_thread(study_id, task_id)`** — отправленные ответы и вложения.
- **`preview_assignment_response(study_id, task_id, message, file_paths?)`** —
  подготовка и проверка ответа без отправки.
- **`submit_assignment_response(preparation_id)`** — только при включённой
  настройке; публикует подготовленный ответ от имени студента.
